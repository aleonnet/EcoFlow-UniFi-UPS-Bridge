## Context

**Como um widget do macOS existe** (medido nesta máquina em 2026-09-06, macOS 26.6.2):
- Um `.appex` em `Contents/PlugIns/` do app, `CFBundlePackageType = XPC!`, `NSExtension → NSExtensionPointIdentifier = com.apple.widgetkit-extension`, sem `NSExtensionPrincipalClass` (o executável é um `@main struct: Widget`). Lido no widget de um app de terceiro instalado aqui (`/Applications/Dropover.app/Contents/PlugIns/ControlWidgetsExtensionExtension.appex` — **assinatura da App Store**: `Authority=Apple Mac OS Application Signing`, `TeamIdentifier=D3Y7QS482H`; NÃO é referência de Developer ID nem de notarização) e nos da Apple (`Stocks.app/…/StocksWidget.appex`). As chaves completas do Info.plist do Dropover: `CFBundleExecutable`, `CFBundleIdentifier`, `CFBundleName`, `CFBundleDisplayName`, `CFBundlePackageType XPC!`, `CFBundleShortVersionString`, `CFBundleVersion`, `CFBundleInfoDictionaryVersion 6.0`, `CFBundleSupportedPlatforms [MacOSX]`, `LSMinimumSystemVersion`, `NSExtension`. **Não existe nesta máquina um widget Developer ID notarizado para servir de referência**; a única prova do caminho de notarização é a aceitação 6 (a própria release).
- Direitos do `.appex` (o mesmo Dropover): `com.apple.security.app-sandbox = true`, `com.apple.security.application-groups = ["<TEAMID>.group.…"]`, `flags=0x10000(runtime)`. O guia de extensões da Apple: *"All templates for OS X app extensions include the App Sandbox … entitlements by default"*.
- **A receita, provada aqui em 2026-09-06 (`scratchpad/prova-widget.sh`)**: o pacote do `dist` assinado com Developer ID + um `.appex` mínimo (o binário do SwiftPM abaixo, Info.plist com as onze chaves do Dropover, `widget.entitlements` = sandbox + grupo, `app.entitlements` = grupo), assinado de dentro para fora com `--options runtime --timestamp --entitlements`, copiado para `~/Applications/River Bridge Prova.app` e aberto: `codesign --verify --deep --strict` passa; `codesign -d --entitlements :-` mostra os direitos certos nos dois; **`pluginkit -m -p com.apple.widgetkit-extension` lista `com.river.bridge-ui-prova.widget(0.9.0)`** com o caminho do appex. O mesmo com assinatura **ad-hoc** (`prova-widget-adhoc.sh`): também registra (`com.river.bridge-ui-adhoc.widget`). O que NÃO foi medido: a renderização na galeria (item humano) e se a extensão em sandbox alcança o contêiner do grupo com Team ID ausente (ad-hoc) — a doc diz que o sistema confere o Team ID; fica como **inferência**.
- **Grupo de aplicativos sem registro na Apple**: `docs/bundleresources/entitlements/com.apple.security.application-groups`: *"In macOS, you can also create app groups … using this identifier format: `<team identifier>.<group name>` — You don't need to register app groups that use this format on the Apple Developer website"*; `xcode/configuring-app-groups`: *"macOS checks that the code signature of processes that try to access the app group container contains the same [Team ID] as app group container ID"*. Medido aqui com um executável de prova (`grupo-min`, as três saídas coladas abaixo no Impact sweep): `containerURL(forSecurityApplicationGroupIdentifier: "8A47D8UNV2.com.river.bridge")` → `~/Library/Group Containers/8A47D8UNV2.com.river.bridge`, gravável, nas três assinaturas (sem direito, ad-hoc com direito, Developer ID + runtime + direito) — para o app SEM sandbox, rodando de um terminal (o contexto de TCC do terminal; o caso do Finder é observável na bancada). A extensão, com sandbox, só alcança o contêiner com o Team ID batendo (inferência da doc, não medida): no gate (ad-hoc) o widget registra mas pode não ler o retrato, e isso é dito.
- **Compila fora do Xcode**: `xcrun swiftc -parse-as-library -target arm64-apple-macos26.0` de um `@main struct: Widget` com `StaticConfiguration` → binário de 74 KB ligado a `/System/Library/Frameworks/WidgetKit.framework` nativo (não o do iOSSupport). O SwiftPM faz o mesmo com um `executableTarget`.
- **Atualização** (`widgetkit/keeping-a-widget-up-to-date` e `timelinereloadpolicy`, lidos): o widget não fica ativo; o sistema renderiza as entradas de uma linha do tempo; **orçamento de 40 a 70 recargas por dia** por widget ("roughly … every 15 to 60 minutes"); entradas com pelo menos ~5 min entre si; `.after(date)` é ELE MESMO um pedido de recarga; `WidgetCenter.shared.reloadTimelines(ofKind:)` quando os dados mudam. A isenção "app em primeiro plano" existe na doc, mas se um app de barra de menu com a janela fechada conta como primeiro plano **não está na doc e não foi medido**: não entra na conta.
- `pluginkit -m -p com.apple.widgetkit-extension` lista as extensões registradas (medido: existe em `/usr/bin` e lista as da Apple) — é a prova de registro.

**O que o app já tem**: o estado chega por SSE em `TelemetryStore.apply` (`TelemetryStore.swift:182-186`); `phase` não tem `didSet` e recebe `.live` a cada mensagem (`:151`, `:178`); o `init` do store recebe `arguments/client/environment` (`:55-57`) e **14 testes constroem `TelemetryStore(…)` e chamam `apply`** (`FormattingTests.swift:34-39` e outros) — qualquer gravação de arquivo no `apply` precisa de destino injetado, senão a suíte e cada cópia de mutação escrevem no contêiner real do dono; o idioma vive em `UserDefaults.standard` do app (`AppPrefs.swift:22-30`), e o `AppPrefs.language.didSet` não conhece o store — o widget é outro processo, com o seu próprio `UserDefaults`; a paleta são 6 triplas RGB em `Theme.swift:9-20` (App) e os tokens `Espaco`/`Raio` em `DesignSystem.swift:37-74` (App); o Core é livre de SwiftUI (grep: zero `import SwiftUI` em `RiverBridgeCore`); todo arquivo do App que usa `Espaco.`/`Raio.` já importa `RiverBridgeCore` (grep, zero exceções). O empacotador (`tools/build-app.sh`) monta o pacote à mão e assina de dentro para fora sem direito nenhum (`assinar()` sem `--entitlements`).

Resultado pretendido: na galeria de widgets aparece "River Bridge" com dois tamanhos; o pequeno mostra o anel de carga com a porcentagem, a fonte (na tomada / na bateria) e a autonomia; o médio acrescenta entrada da rede e consumo. Os dados são os do último retrato que o app gravou; velho, o widget diz a hora e, depois de meia hora sem app, mostra traço com "abra o River Bridge".

## Risk band

**high** — muda a assinatura do app (direitos), o empacotamento e a notarização; nada muda no serviço nem no que desliga aparelhos. Regras: cada regra nova refutada por mutante; prova de estrutura e direitos no empacotador; registro medido com `pluginkit`; revisão fria do diff; o visual do widget na área de widgets é item humano.

## Changes, per file

**Core (Swift)**
- `RiverBridgeCore/Tokens.swift` (**novo**, movido de `DesignSystem.swift:37-74`): `public enum Espaco`, `public enum Raio`. `RiverBridgeCore/Paleta.swift` (**novo**): `public enum Paleta { public struct RGB { r,g,b: Double }; static let tomada, bateria, baixa: [RGB] }` (as 6 triplas de `Theme.swift`).
- `RiverBridgeCore/RetratoDoWidget.swift` (**novo**, puro): `struct RetratoDoWidget: Codable` (D2); `static func de(estado:fase:emPortugues:agora:) -> RetratoDoWidget`; `static func deveRecarregar(anterior:novo:) -> Bool` (D3; sem relógio); `static let grupo = "8A47D8UNV2.com.river.bridge"`, `static let nomeDoArquivo = "retrato.json"`, `static func url(fm:) -> URL?` (containerURL); `func gravar(em:)` / `static func ler(de:)`. `IdadeDoRetrato` (D4): `enum Mostra { valores, valoresComHora(String), traco }` + `static func para(retrato:agora:)`.
- `RiverBridgeCore/TelemetryStore.swift` — `init` ganha `retrato: URL? = nil` e `aoRecarregarWidget: (() -> Void)? = nil`; `gravarRetrato()` (pública): monta o retrato, compara com o último gravado (`Equatable`), grava só se mudou e, se `deveRecarregar(anterior:novo:)`, chama a closure; chamada em `apply` (`case "state"`) e em `phase` `didSet` quando `oldValue != phase`.
